# Isaac 训练迁移交接

日期：2026-10-20。目标是把当前 v3 机器人迁移到另一台机器，先训练平地稳定，再训练移动、小陀螺以及有限斜坡与交界地形。环境安装见[环境说明](../ENVIRONMENT.md)，抽取实现和原始接口见[框架说明](ROBOT_FRAMEWORK_20261020.md)。

现有 `spin_*_env.py`、SB3 VecEnv 和 C GUI 仍包含 MuJoCo 运行逻辑。不能直接替换 import 就获得 Isaac 训练环境。`wheel_legged/interfaces.py` 与 NumPy 运行循环用于对照；GPU 大规模训练需保持相同物理约定、另写 Torch/device 实现，物理子步内不要调用 `.cpu().numpy()`。

## 2. 资产、闭链与力矩映射

源资产为 [v3 XML](../../model/v3/COD-2026RoboMaster-Balance-v3.xml)、同级 `meshes/`，标定为 [v3_robot_calibration.json](../../config/v3_robot_calibration.json)。来源哈希见 [PROJECT_MANIFEST.json](../../PROJECT_MANIFEST.json)。

导入 USD 或经 URDF 转换时逐项核对质量、惯量、质心、网格尺度、关节轴和限位、左右镜像、默认姿态、碰撞体与轮地接触。MJCF 的闭链约束必须在目标物理引擎重建；普通开链 URDF 不会自动保留其力学效果。先用单腿和固定机体工况验证拓扑、约束漂移及关节角到腿长的映射，再启用自由机体。

六电机物理输出顺序固定为：

```text
0 Left_front_joint
1 Left_rear_joint
2 Left_Wheel_joint
3 Right_front_joint
4 Right_rear_joint
5 Right_Wheel_joint
```

腿通道 `[0,1,3,4]`，轮通道 `[2,5]`。后端按名称查找真实索引；左右轮正负号取决于真实轴向，用单轮正力矩测试确认，不能只看关节名。角度 rad、速度 rad/s、长度 m、关节力矩 Nm。

MuJoCo 的腿/轮 ctrl 增益 50/10 只属于旧引擎执行器换算；Isaac 接口接受 Nm 时直接传关节 Nm。外部 PD/P 接管时关闭相应的内部位置/速度 drive，避免重复驱动；模型实际的被动阻尼应单独核对。连杆产生的机体受力/力矩应由正确的关节轴、连杆、闭链和接触传递，不能额外重复给机体施加同一份反作用力矩。`core/wrench.py` 的 Jacobian/虚功用于对照力映射，不能把六个关节力矩直接相加当成机体力矩。

## 3. 部署观测与特权信息

控制坐标：x 前、y 左、z 上，世界 z 上；公共四元数为 `wxyz`、world-from-control。Isaac 各 API 的四元数顺序和局部/世界参考系逐一验证，不能按 API 名猜测。

单帧 25 维，依次为：

| 分量 | 维度 | 约定 |
| --- | --- | --- |
| 机体角速度 | 3 | 控制机体系，rad/s |
| projected_up | 3 | 世界 +Z 投影到机体系；水平为 `[0,0,1]` |
| 命令 | 3 | 前进 m/s、yaw rad/s、目标腿长 m |
| 四腿电机角度 | 4 | LF、LR、RF、RR，rad |
| 六关节角速度 | 6 | LF、LR、RF、RR、LW、RW；与输出顺序不同 |
| 上一次策略动作 | 6 | 含义和缩放随策略元数据保存 |

姿态三维使用 `projected_up`，不是直接填三个 Euler 角，也不是 Isaac 示例中常见的向下 projected gravity。IMU 加速度接口需区分 specific force 和含重力线加速度，防止重力重复处理。

当前归一化按分组除以 `[5]*3 + [1]*3 + [1.2,3.5,0.2] + [1]*4 + [10]*4 + [30]*2 + [1]*6`，再裁剪到 `[-20,20]`。移植时与 [observations.py](../../scripts/wheel_legged/core/observations.py) 做数值对照。

新目标使用总计 5 帧、包含当前帧的历史，展开为 125 维，按旧到新排列。局部环境 reset 时只重置对应实例的历史、上一动作及伺服状态。历史编码器压缩后与当前帧拼接的结构可参考已有 Torch 网络，但旧紧凑模型使用 25×6，不能无检查复用 checkpoint；125 维缓冲本身也不代表新 encoder 已训练完成。

Actor 仅用部署传感器和命令。Critic、奖励、评估及辅助监督可以使用世界位置/线速度、接触状态/接触力、地形等特权量，这属于非对称 Actor-Critic，可配合 PPO。接触/地形目前不在 `TruthState` 中，需放入训练专用结构，禁止混进 Actor 输入。评估漂移使用世界真值，不使用可能打滑的轮速里程计代替验收基准。

## 4. 动作、伺服与接管

计划中的新动作是四腿关节位置目标加两轮速度目标，经外部腿 PD / 轮 P 产生六路物理 Nm。策略归一化动作到物理目标的偏置、缩放、限位和动作更新频率必须在任务中明确实现并记录。现有 wrench/residual checkpoint 的六维动作不是这套语义。

参考配置 [rl_joint_pd.json](../../config/rl_joint_pd.json)：腿 `Kp=120, Kd=1.6`，轮 `Kv=0.50`；力矩限制 `[60,60,10,60,60,10]` Nm，力矩变化率限制 `[300,300,40,300,300,40]` Nm/s。这些是原 1 ms 固定机体台架基线；PhysX 接触和闭链不同，需先复测，不可当成整车稳定保证。

RL 与 PID/LQR 对整套电机输出采用互斥接管。RL 接管时保留确定的目标伺服、限幅与变化率保护，不叠加 PID/LQR 平衡力矩，不额外加入力矩 PI。未来接管课程需要覆盖 PID→RL、LQR→RL、原生切换过程中→RL，并记录切换状态、瞬态和伺服记忆状态处理。

## 5. 分阶段训练与验收

1. **物理接口**：单关节正负方向、默认姿态、重力/IMU、闭链、腿长几何、力矩单位；固定机体分别测腿位置阶跃和轮速度阶跃，再加扰动。与 MuJoCo 参考记录对照，排除映射错误。
2. **平地 pitch 起步**：先固定简单命令和地形，以 pitch 稳定的稠密奖励开始。记录奖励各分项和真实物理指标；随后恢复完整 roll/pitch 平衡，不能只凭单轴奖励声明整车可用。
3. **移动与旋转**：分别测 W/S/A/D 等价命令各 5 s、最高/最短腿长变化、小陀螺 5 s。用世界位移、yaw 累计角度和速度验证实际运动，不能只看腿在动或动作有响应。
4. **位置恢复**：旋转中允许有限漂移，但必须能回到允许范围。奖励同时考虑每步位置偏离、超范围成本、回归进展和旋转速度，保留远离目标时仍有区分的惩罚，避免只用远处趋于零的指数奖励。单独记录最大偏移、终点偏移、回归时间、超界时长和完成转角，不能仅看总奖励或存活率。
5. **地形扩展**：从平地到有限斜坡、平坡交界、不同朝向/站位/双轮高度差，再加摩擦、质量、IMU、执行器延迟与接管随机化。短/中/长腿与正反转分档评估，使用固定种子和同场景传统控制对照。

斜坡阶段以 roll 稳定为主，pitch 权重较弱，同时约束旋转跟踪和可恢复的漂移。腿长分档基准需沿用已讨论定义：旋转到双腿连线沿坡向时，高处一侧的短腿长度；不是每一步直接取两腿最小值。普通姿态下需要几何映射，部分在坡上的场景必须验证映射误差。此迁移分支只记录要求，尚未提供统一的 Isaac 实现。

每阶段保存固定评估工况、零策略/传统控制对照、奖励分项、模型元数据及失败轨迹。通过该阶段再扩展难度；此前日志中的高存活率、低 roll RMS 不等于已满足位置恢复要求。
