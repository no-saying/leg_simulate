# Slope Spin RL (2026-10-16)

## Task

The current finite-ramp task and randomized controller handovers are described in
[SPIN_MIXED_RL_20261016.md](SPIN_MIXED_RL_20261016.md). Training/evaluation now
default to that V3 mixed task. This document describes historical V2; use
`--terrain plane` to reproduce its 328-input environment.

The subsequent baseline-control diagnosis and accepted fixes are recorded in
[SPIN_BOUNDARY_20261016.md](SPIN_BOUNDARY_20261016.md). The historical v2 numbers
below predate those changes. The policy interface and reward are unchanged, but
new evaluations must use the same controller build for baseline and policy.
Current outputs record the controller/physics provenance; existing v2 checkpoints
remain offline experiment candidates.

Independent residual PPO task using mjbatch and the existing deployed PID/LQR
controller. Roll stabilization is the main objective; pitch shaping is weak.
The GUI does not load this policy automatically. New checkpoints are independent
of the existing jump policy and cannot be used by its C exporter.

Physics and the complete C controller run at 1000 Hz. Policy inference runs at
50 Hz, holding each requested action over 20 physical steps. PPO uses a 256/256
MLP with Tanh activations, gamma=0.999, GAE lambda=0.98, fixed observation
scaling and an eight-frame sensor history. Initial exploration standard deviation
is exp(-1), approximately 0.37. The current task version is `slope_spin_v2`.

## Inference Contract

`model.predict(obs, deterministic=True)` accepts float32 `(N,328)` and returns
actions `(N,5)`. A single robot may pass `(328,)` and receive `(5,)`.
History runs from oldest to newest; reset repeats the initial frame eight times.
Each frame has this exact order, before normalization:

| Indices | Quantity | Units | Scale |
| --- | --- | --- | --- |
| 0:3 | World-up direction expressed in control body frame | unit vector | 1 |
| 3:6 | Body gyro XYZ | rad/s | 5 |
| 6:9 | Accelerometer XYZ, including supported gravity | m/s2 | 20 |
| 9:11 | Raw left/right wheel encoder rates | rad/s | 30 |
| 11:13 | Calibrated left/right leg lengths | m | 0.2 |
| 13:15 | Calibrated left/right length rates | m/s | 0.5 |
| 15:17 | Calibrated left/right swing positions | m | 0.05 |
| 17:19 | Calibrated left/right swing rates | m/s | 0.5 |
| 19 | Controller's forward velocity estimate | m/s | 2 |
| 20:22 | Existing per-wheel encoder/IMU mismatch signals | controller units | 5 |
| 22:24 | Existing per-leg obstacle retraction | m | 0.04 |
| 24 | Requested nominal physical leg length | m | 0.2 |
| 25 | Requested forward speed, zero for this task | m/s | 2 |
| 26 | Independent ramped task yaw-rate target | rad/s | 3.5 |
| 27 | Current supervisor LQR mixture | fraction | 1 |
| 28:33 | Previous clipped policy action | normalized | 1 |
| 33:36 | ZYX Euler roll/pitch/yaw rates from attitude and gyro | rad/s | 5 |
| 36:41 | Filtered and slew-limited residual action state | normalized | 1 |

Divide by these scales and clip to [-20,20]. No true XY position, true body
velocity or true slope is present in the actor input. Sensor and actuator state
are captured from the C controller. World truth is used for reward/evaluation.
The C bridge's raw yaw field is the base controller command; Python explicitly
uses the task's physical ramped reference in observations. This same reference
is supplied to the base controller and used by the reward, including deceleration.
The appended residual state is after the 40 ms filter and slew limiter, before
mechanical limits and final actuator protection; it is not a measurement of the
final applied actuator correction.

| Action | Physical residual at +/-1 |
| --- | --- |
| 0 | Differential physical leg length +/-0.010 m |
| 1 | Common physical leg length +/-0.010 m |
| 2 | Common swing reference +/-0.005 m |
| 3 | Common wheel torque +/-0.20 Nm |
| 4 | Differential wheel torque +/-0.15 Nm |

Physical `dL_left = common + differential`, `dL_right = common - differential`.
The existing extension convention has the opposite sign. Wheel torques are
added after mixer weights and before output speed protection; on v3 the control
increments are `(common-yaw)/10` and `(common+yaw)/10`. Do not apply the mixer
weights a second time. All actuators still have final limits.

Residuals have a 40 ms low-pass filter and a normalized slew limit of 10/s,
updated every physical step. Obstacle retraction forbids a positive length
residual on the affected leg. The supervisor continues choosing PID/LQR/energy
from actual posture; training disables its automatic self-right sequence and
terminates failed episodes instead. LQR eligibility is not selected by leg length.

Enabling the residual interface explicitly permits full-travel leg references
and turns within physical leg-length bounds (8 mm measurement margin). Without
that interface the previous manual turn window is retained. This matters:
the old 0.066-0.165 m turn window cleared yaw requests at both extreme lengths.
The task target is independent of such output gates, so stopped rotation never
becomes perfect tracking when the base controller clears its command.

## Reset and Curriculum

Extension covers [-0.093,+0.070] m, corresponding to nominal leg lengths
[0.047,0.210] m. Ten percent of samples use each exact endpoint, with the rest
continuous. Actual lengths under load are measured, not assumed equal to targets.
Initial heading covers a full revolution; rotation direction is equally sampled.

Reset establishes nominal height on flat ground for 2.5 s, rotates the robot and
plane consistently, then runs 20 ms on that environment's slope. The policy acts
immediately after this transition. This is a slope-introduction reset, not a claim
of a previously stabilized steep-slope equilibrium. There are no retry/rejection
loops that discard failed preparations. Initial motion remains in the episode.
Balls are moved away for the first curriculum; floor friction is fixed at 1.

Every default episode lasts 20 s: hold 0-1 s, turn 1-16 s, stop/recover 16-20 s.
Yaw follows the existing nominal-height schedule (2.76 rad/s short/middle,
1.38 rad/s long, continuous interpolation) and a 0.8 rad/s2 ramp.
The nominal-height target is independent of RL's height adjustment.
Four seconds allow the maximum rate to ramp fully to zero. Diagnostics distinguish
hold, accelerate, spin, decelerate and recover. The explicit physical-rate command
bypasses a second application of the GUI's nominal-height scheduling.

Advance maximum slope 3 -> 5 -> 8 -> 10 -> 15 degrees after held-out evaluations
meet the task requirements. Slope sign and initial heading are randomized.
Mass/friction/noise/latency and obstacle randomization are future curriculum
extensions, not implemented in this initial task.

## Reward and Failure

Reward density is integrated using physical dt on every 1 ms step:

- Survival: +1/s.
- Roll: -5 times squared error normalized by 3 degrees, capped at 4.
- Roll rate: -1.5 times squared rate normalized by 30 deg/s, capped at 4.
- Pitch: -0.25 times squared error normalized by 8 degrees, capped at 4.
- Yaw tracking: 2 - 0.5 Huber(abs(actual-target)/0.6 rad/s), with the
  linear argument capped at 6. Huber(e) = 0.5 e^2 for e <= 1, otherwise e - 0.5.
- Speed and displacement: -0.2 times their normalized squared penalties.
- Nominal-height tracking: -0.1 times its normalized squared penalty.
- Action effort: -0.02 mean(action^2).
- Action changes: -0.05 mean((action-previous)^2).

ZYX roll/yaw derivatives are computed from attitude and body gyro. Raw gyro_x
is not used as roll_dot during tilted spin. Roll and pitch targets are gravity
upright, not the terrain normal. Small balance corrections remain possible.

Failures include |roll|>35 degrees, |pitch|>45 degrees, nonfinite physics, more
than 3 m drift, or persistent under-rotation after the six-second startup grace.
Under-rotation means signed actual yaw rate below 20% of target for over 2 s.
Failure costs 10 plus 35 times remaining episode seconds. This exceeds the
remaining worst bounded reward loss and prevents reward improvement by early
termination. Time limits preserve SB3 terminal observations and bootstrapping.

Logs report roll RMS/peak, yaw-rate RMSE, integrated actual yaw angle, drift,
episode duration, physical failure and rotation stalls. Per-phase logs also include
pitch RMS/peak, maximum speed and drift. Failure reasons, first failure phase/time
and integrated reward components (including terminal cost) are retained.
Yaw metrics measure actual rotation, not wheel speed or received key commands.

## Commands

Run from the repository root using the existing isolated MuJoCo 3.14 environment:

```bash
.venv-mjbatch/bin/python scripts/train_spin_rl.py \
  --terrain plane \
  --steps 327680 --envs 32 --threads 8 --slope 3 --rollout 512 --epochs 10 \
  --out logs/rl_training/spin_v2_327k

.venv-mjbatch/bin/python scripts/train_spin_rl.py \
  --terrain plane \
  --resume logs/rl_training/spin_v2_327k.zip --steps 500000 --slope 5 \
  --out logs/rl_training/spin_v2_stage2

.venv-mjbatch/bin/python scripts/eval_spin_rl.py \
  --terrain plane \
  --slopes 0 3 5 8 --extensions -0.093 -0.04 0 0.04 0.070 --headings 0 90 \
  --out logs/rl_training/spin_baseline_full.json

.venv-mjbatch/bin/python scripts/eval_spin_rl.py \
  --terrain plane \
  --model logs/rl_training/spin_v2_327k.zip \
  --slopes 0 3 5 8 --extensions -0.093 -0.04 0 0.04 0.070 --headings 0 90 \
  --out logs/rl_training/spin_policy_full.json

.venv-mjbatch/bin/python -m pytest \
  scripts/tools/test_spin_rl.py scripts/tools/test_jump_rl_batch.py -q
```

Compare baseline and policy on the SAME MuJoCo version and reset/task contract.
The baseline uses zero residual actions with the same full-range turn allowance.
The previous GUI/native slope tests used MuJoCo 3.10, a different initialization
and a five-second spin, so they are not interchangeable with these measurements.

The accompanying JSON stores scaling and policy interface metadata; episode
metrics are appended to `.episodes.jsonl`. Resume retains PPO hyperparameters
from the checkpoint; CLI rollout/epochs apply to newly created models.
Every 100,000 transitions, evaluation uses 20 fixed cases: slopes 0/3 degrees,
extensions -0.093/-0.04/0/+0.04/+0.070, both directions, heading zero. A final
evaluation is also saved. The v1 264-input checkpoint is incompatible with the
v2 328-input contract; v2 starts fresh.

## V2 Verification

- Native controller compilation succeeded with `make -C control -j4`.
- Spin and jump batch regression: 15 tests passed in 10.62 s.
- Added checks cover Euler-rate coupling, filtered residual feedback, physical
  reference equality during deceleration, a full stop with recovery time, failure
  phase/reason logging and reward component accounting.
- Baseline over 24 cases (0/3/5/8 degrees, three endpoint/middle lengths, both
  directions): 8 completed; mean trial roll RMS 1.365 degrees, mean maximum
  drift 1.824 m, mean duration 14.998 s. Failures: six rotation stalls, five
  pitch-limit failures during recovery, five drift-limit failures during spin.
  These diagnostics distinguish failure types; low roll alone is not acceptance.
- The current v2 training and evaluation artifacts use the `spin_v2_` prefix.

### V2 Training Outcome

Fresh training completed 327,680 transitions in 955.1 s, using 32 environments,
eight physics threads, 512-step rollouts and ten PPO epochs. Saved parameters
and deterministic predictions are finite; the verified interface is 328 -> 5.
Both actor and critic retain two 256-unit Tanh layers. No network expansion or
unverified gyroscopic torque feedforward was introduced. Known kinematics supplies
the Euler-rate features; the existing controller supplies the residual actuator
filter state.

Fixed 20-case evaluation, identical reset/task contract throughout:

| Checkpoint | Completed / 20 | Mean trial roll RMS (deg) | Mean maximum drift (m) |
| --- | --- | --- | --- |
| Zero-residual baseline | 13 | 0.7011 | 1.0052 |
| 100,000 | 12 | 0.6833 | 0.9747 |
| 200,000 | 12 | 0.6940 | 1.0673 |
| 300,000 | 13 | 0.6901 | 1.1019 |
| 327,680 | 12 | 0.6745 | 1.1629 |

The final model has slightly lower roll RMS but fewer completed trials and more
drift. Early failures shorten the RMS measurement, so this does not demonstrate
better stabilization. Neither checkpoint is accepted as an improved controller.
The 300,000-step checkpoint is retained because it completes more cases than the
final checkpoint; it still does not exceed baseline completion.

At the final checkpoint, the three interior length settings each complete 4/4;
both endpoints complete 0/4. Longest-leg failures occur during recovery and reach
the pitch limit. Shortest-leg failures are three rotation stalls and one drift
escape. This identifies the boundary cases requiring further control/action
authority diagnosis; increasing roll weight or network size is not supported by
this experiment. Pitch remains weakly shaped, while physical failure still incurs
the original terminal cost. No automatic slope-curriculum advance is justified.

Additional 24-case comparison uses slopes 0/3/5/8 degrees, extensions
-0.093/0/+0.070, both directions and heading zero. The 5/8 degree slopes are
outside training; this grid still does not establish generalization to all headings.

| Controller | Completed / 24 | Mean trial roll RMS (deg) | Mean maximum drift (m) | Mean duration (s) |
| --- | --- | --- | --- | --- |
| Zero-residual baseline | 8 | 1.3650 | 1.8243 | 14.998 |
| 300,000 checkpoint | 9 | 1.3340 | 1.9382 | 15.344 |
| Final 327,680 checkpoint | 7 | 1.3601 | 1.9983 | 14.605 |

The 300,000-step model is the preferred experiment candidate based on completion
in both grids, rather than assuming the last checkpoint is best. Its one-case
completion improvement and small roll reduction come with increased drift. It
still does not satisfy the slope-spin task across the full length range. No
controller in this comparison completes any 8-degree case. Final-model failures
are eight drift escapes, five rotation stalls and four recovery pitch failures;
none reaches the roll failure threshold.

Here, "completed" means reaching the 20 s time limit without a termination
condition. It is not a strict yaw-tracking acceptance test. For example, the
300,000-step shortest-leg flat-ground case that completes rotates only 6.50 rad
in magnitude over the episode, versus approximately 41.4 rad commanded. The
current stall detector catches sustained near-zero rotation, but intermittent
under-rotation can still reach the time limit. Actual angle and yaw RMSE must
therefore accompany completion counts; this case is not successful spin tracking.

## Historical V1 Verification

They must not be compared directly with v2 as evidence of policy improvement.

- Native controller compilation succeeded with `make -C control -j4`.
- Spin task plus existing jump batch regression: 13 tests passed in 10.06 s.
- Tests cover actual actuator response for all five residuals, physical wheel
  torque units/signs, zero-residual parity at nominal height, both extreme turn
  commands, per-environment slope physics/native warmup parity, sensor-only
  observations, reset isolation, history order, stall failures and time limits.
