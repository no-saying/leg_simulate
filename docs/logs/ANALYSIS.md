## 2. 传感器约束

控制器运行时只使用现实机器人可获得的信号：

- IMU 四元数、角速度、加速度。
- 左右轮编码器位置和速度。
- 四个腿关节编码器位置和速度。
- 六个执行器反馈力矩。

世界坐标 `body_pos`、机体真实高度、真实平面位置只用于日志、GUI 轨迹和仿真质量判断，不进入控制闭环。

`controller.c` 传给 `balance_update()` 的数组为：

```text
[pitch, pitch_rate, lw_vel, rw_vel,
 acc_mag, acc_x, acc_z, yaw, yaw_rate,
 lw_pos, rw_pos,
 lf_pos, lr_pos, rf_pos, rr_pos,
 lf_tau, lr_tau, rf_tau, rr_tau,
 lw_tau, rw_tau,
 lf_vel, lr_vel, rf_vel, rr_vel]
```

## 3. 当前控制结构

当前默认走简单三环路径：

```c
#define USE_SIMPLE_THREE_LOOP 1
#define SIMPLE_PURE_BALANCE 1
```

环路频率：

- pitch 平衡环：每个物理步执行，XML `dt=0.001s` 时为 1000 Hz，大于 500 Hz。
- 速度/里程计环：100 Hz。
- yaw 环：50 Hz。

这三环是并联生成控制量，不是串联 PID。位置环不直接输出轮速，而是规划 `target_pitch`；pitch 环再用身体倾角生成共模轮扭矩。yaw 环只输出差动扭矩，并在最终混控时被权重限制。

## 4. 机械和模型标定修改

### 4.1 轮子参数

轮半径保持与 MJCF 模型一致：

```c
#define WHEEL_RADIUS 0.058f
```

没有再把轮半径调大。这样轮编码器里程计不会靠错误半径“补偿”控制问题。

左右轮关节物理参数调整为：

```xml
damping="0.08"
armature="0.002"
```

更大的阻尼和转动惯量曾经能压轮速，但会明显损坏 pitch 恢复，甚至翻车，所以当前保留中等值。

### 4.2 腿摆中位

腿摆名义角从控制宏统一：

```c
#define BALANCE_LEG_SW_NOM 0.23f
```

这个值用于四腿目标角映射，目的是让平衡点更贴近当前模型质心位置。质心偏差仍然是后续需要继续标定的核心问题。

## 5. 里程计与打滑处理

当前里程计以轮编码器为主，但先做现实可用的接触可信度判断：

- 离地：IMU 加速度模值低且腿执行器负载低。
- 冲击：IMU 加速度或机体系前向加速度异常大。
- 打滑：轮速加速度与 IMU 前向加速度残差过大。
- 静止更新：pitch、pitch rate、轮速和 IMU 加速度都足够小时，认为速度为零。

关键点：

- 离地和冲击时不积分轮速。
- 打滑时大幅降低轮速可信度，只允许很小的保守速度积分。
- 轮速和 IMU 走同一组 FIR/低通处理，避免相位差导致误判。
- 控制只使用 yaw 相对起点投影后的里程计；世界坐标只显示。

## 6. 速度规划和 pitch 决策

现在的回原点控制不是直接“命令轮速”，而是通过位置误差决定 `target_pitch`：

```text
位置误差 -> 目标速度 v_ref -> 速度误差 -> target_pitch -> pitch 平衡环 -> 轮共模扭矩
```

这和真实平衡车逻辑一致：要往回走，就让车体产生相反方向的倾角趋势，而不是直接抢轮子。

最近一次目标 pitch 辨识结论：

- 正 `target_pitch` 会使 `vh/wv` 增大。
- 响应有约 0.2 到 0.3s 的延迟。
- 因此速度规划使用 `plan_neutral = -K * v_err`，这是当前轮速收敛能明显改善的关键符号修正。

当车正在回原点时，规划增益较温和；当车继续远离原点时，增益和最大目标 pitch 会提高，用于快速压住轮速趋势。

## 7. 输出级轮速保护

`controller.c` 最终混控处增加了共模轮速保护：

```text
pitch_mix = 0.6 * balance_tau
yaw_mix   = 0.4 * yaw_tau
```

若轮速超过阈值，输出级只覆盖共模 pitch 扭矩，不覆盖 yaw 差动项。保护项带 pitch gate：pitch 还没回到可控范围时不长期累积强刹车，避免救车阶段直接把车打翻。

这层是兜底，不是主要回原点策略。主要策略仍然是目标 pitch 规划。

### 8.1 原点收敛重调（2026-08-03）

上一版 60s 末端 `final_xh=-1.62m`，随后近场实验发现真正形态是
`+-0.45m` 的持续极限环：回程接近零点时速度约 0.5 m/s，目标俯仰角要过零后才
变向，刹不住就冲到另一侧，周而复始。

本轮修改（全部集中在 `control/include/control_config.h` 和
`control/balance/balance_core.c`）：

```text
1. 减速斜坡 SIMPLE_ORIGIN_APPROACH_RAMP_POS=0.35m
   v_ref 按剩余距离线性收窄，接近零点时先减速而不是冲过去。
2. 近场捕获 SIMPLE_ORIGIN_STOP_POS=0.16m / STOP_V=0.08
   贴近原点仍有速度时目标速度归 0，增益/限幅保持温和。
3. 直接位置补偿随速度衰减 SIMPLE_ORIGIN_DIRECT_SPEED_GATE=0.30m/s
   高速回程不再叠加位置项，避免往运动方向继续加速。
4. 直接位置补偿增强 DIRECT_PITCH_KP=0.35、MAX=0.08rad
   低速贴零时能真正启动爬行，消除停在原点外侧 0.1~0.16m 的静摩擦死区。
5. 释放窗口放宽 SIMPLE_ORIGIN_RELEASE_POS=0.10m
   回到原点且速度足够小时位置记忆向 0 衰减，不再被残余偏置拉住。
6. 近原点停车阻尼 SIMPLE_PARK_VEL_DAMP=12 -> 18
   靠近直立时更强地压轮速。
7. 目标俯仰滤波 SIMPLE_NEUTRAL_TAU=0.18 -> 0.12s
   减少回程变向时目标俯仰的响应延迟（小信号辨识确认正目标俯仰=正向加速）。
8. 近场直接轮扭矩模式 SIMPLE_ORIGIN_DIRECT_TAU_ENABLE（默认关）
   保留可开关实现：低速贴零时保持当前俯仰角、用直接刹停/爬行扭矩回原点，
   避免目标俯仰阶跃造成“仰身冲量”把车反向推 0.3~0.5m。
```

关键认识：这个模型里目标俯仰角一变化，身体仰身过程本身会把轮子先反向推
（一次 2~4° 的仰身可产生 0.3~0.5m 位移），所以近场反复尝试“用俯仰刹车”都会
触发正反馈。收敛组合最终用增强的**直接位置补偿 + 更快 neutral + 更强 park
阻尼**，而不是让近场俯仰命令变大。

当前默认参数 60s 结果（log: `logs/final_default_60s_20260803_195456.log`）：

```text

tail(>30s): xh -0.21 .. -0.03, mean|x|=0.10
tail(>40s): xh -0.21 .. -0.04, mean|x|=0.12
final_xh = -0.06 m, final_vh = +0.04 m/s
max_abs_pitch = 9.9 deg（只出现在前 20s 初始落地恢复）
```

对比：

```text
                   修改前(极限环)        修改后
位置幅度            持续 +-0.45m         +-0.21m（20s 后）
位置均值            ~0.3m                0.09~0.12m
尾部速度            +-0.6 m/s            +-0.25 m/s
收敛时间            不收敛               ~23s 后不再超 0.15m
```

仍然没有完全停在 0：车在 `-0.05~-0.13m` 附近做小幅振荡，偶尔漂到 `-0.21m`
再爬回，原因仍是低速爬行启动死区和 `-0.1m` 外的偏置。下一步方向：

1. 标定质心/腿摆中位（`BALANCE_LEG_SW_NOM`），让自然平衡俯仰角和零位一致，
   直接消除稳态负偏置。
2. 若要完全消除偶发 `-0.2m` 漂移，可打开 `SIMPLE_ORIGIN_DIRECT_TAU_ENABLE=1`
   并配合更小的远端回程俯仰上限（当前远端仍用 `+-0.18/0.13rad`）。
3. `+-5deg` 内接 LQR/MPC 精调仍按原计划，只做微调项，不承担大角度恢复。

### 8.2 GUI 手动驾驶与“停车保持”语义（2026-08-03）

新增 GUI 功能：`V` 切换视角（跟随/俯视/车后/侧面），`W/S` 前后，
`A/D` 原地转圈，`R` 复位，`B`/`L`/`ESC` 沿用。手动指令通过
`balance_set_manual()` 注入平衡核心：

```text
1. 手动驾驶 = 虚拟保持点跟踪: W/S 指令斜坡化后积分成 hold_pos，
   原“回原点”机制改成跟踪 hold_pos，不直接改写 neutral，避免仰身冲量。
2. 停车保持语义: 松开按键后 hold_pos 冻结在当前指令位置，车停在原地；
   空闲且 |v|<0.12、|pos-hold|<0.15 时 hold_pos 以 0.5/s 缓慢跟随车身，
   因此“回零点”指的是维持静止点，而不是回启动原点。
3. A/D 转向: 进入手动时把当前航向锁为新 yaw 零点，直接给偏航角速度
   (斜坡化)，松开后保持当前朝向。
4. 防翻: 手动模式跟踪增益缩放 0.65、超速刹车(>0.8m/s 叠反向俯仰)，
   实测 max|v|≈1.3-1.5 m/s、max|pitch|≈6°、max|roll|≈1.5°，不再翻车。
5. 侧翻保护: |roll|>0.55rad 持续 0.2s 判定摔倒，轮扭矩停机，
   GUI 显示 [FALL] press R，按 R 复位到初始姿态并重新平衡。
```

手动行驶实测（headless `MANUAL_TEST=f@8`）：按住 W 约 8s 从 0 开到
~11.4m，松手后 17s 位置保持 11.43m 不动，不再回启动原点。

## 11. 轮毂减速比 + 手动原地差速转向(2026-08-03)

### 模型侧(MJCF)

- 轮执行器改为 `gainprm=1, gear=10`，ctrl 直接是电机侧扭矩，轮上扭矩 = 10×ctrl；
  控制层 `/10.0` 混控不变，电机扭矩自动为轮上扭矩的 1/10(10:1 减速的扭矩映射保留)。
- **反射惯量保留轻轮(armature 0.002, damping 0.08)**：实测 N²·Jm=0.05 的重轮会让
  轮腿机构出现自激 pitch 振荡(松手静止约 10s 后起振，与腿伺服耦合，扫遍腿增益/
  扭矩/阻尼/死区都压不住)。转向 bug 的真正根因是差速速度环正反馈符号错误(已修)，
  不需要重轮压速度；轻轮 + 修复后的速度环即可稳定原地转。

### 控制侧必须同步改的参数(已写进 control_config.h 默认值)

- `SIMPLE_PITCH_KP 240→800`、`SIMPLE_PITCH_KD 70→250`、`SIMPLE_TAU_RUN/START 72→24`。
  原增益在重轮下救不住倾角，实测车无指令漂到 3 m/s；此组可稳定保持。
- `SIMPLE_MANUAL_YAW_MAX 2.5→12`、`SIMPLE_MANUAL_YAW_RATE_KP 1.5→5`。
  俯仰保持的共模扭矩会占掉大部分轮上力矩余量，小差动扭矩推不动原地转。
- `SIMPLE_MANUAL_NEUTRAL_SLEW 0.1→0.3`：0.1 给速度环加太多相位滞后，
  按住 W 会“前进→后退”脉冲循环(实测 10s 后退 40 次)；0.3 消除。
- `SIMPLE_MANUAL_STOP_KP 0.1→5`(bang-bang)：松手刹车在低速只给 4~5° 倾角，
  车以 0.2m/s“后仰前栽”爬行停不下来；顶满 10° 才能真正刹停。
- `SIMPLE_ORIGIN_DIRECT_PITCH_KP/MAX 0.35/0.08→0`：重轮下纯比例位置补偿
  维持 pitch 慢周期极限环(±0.3m 永不停)，关掉后 10s 收敛到 ±0.06m。

### 代码修复(与减速比配套发现的真 bug)

1. **手动偏航方向反了**: 误差公式是 `yr + ref`，稳态 `yr = -ref`，
   所以手动 ref 必须取反(`yaw_rate_ref_pb = -manual_yaw`)；GUI 的 A/D 映射同步修正。
2. **松手后 yaw 停不住**: yaw 门控公式方向反了，`|tau|<MIN` 时把偏航清零，
   俯仰一平静 yaw 就没人管。改为俯仰平静时偏航全权可用、大俯仰救车时才让位。
3. **零指令漂移**: 手动无前后指令时原代码把 neutral 直接清零，
   速度/位置反馈全丢，车自行加速到 3 m/s。现在零指令走 auto 级保持
   (相对 hold_pos 维持当前点，不追回启动原点)，并有静止死区。
4. **W/S 低速档符号**: 速度跟踪公式 `neutral = -kp*v_err` 只在正方向成立，
   重轮下 S 从静止起刹不动(原轻轮可倒车)；此问题在减速比下被放大，
   需要继续整定(见下)。
5. 轮速环(特殊分支/后续硬件环用): 右轮反馈取反+ref 取反=正反馈，
   已改回原始反馈；去掉与速度环打架的电流环；加 Kd=0.10 阻尼。

### 实测行为(最终默认: 轻轮+原增益240/70/72+符号修正, headless, 90s 混合)

- 启动: 温柔(不再被推出 5-7m)，车保持在起点附近。
- 漂移: 松手后 ~0.02 m/s 慢爬(直接位置补偿符号已修正，+倾角会让车向后跑，
  原公式负反馈会放大漂移成跑飞)。
- yaw 保持: 松手后 70s 漂移 <3.5°。
- pitch: 保持期 -0.5..+4.1°，无持续振荡、无修正尖峰。
- 速度: 前进 ~0.8-1.0 m/s、S 真后退、转向正常。
- 已知限制: 静止 2.5 分钟以上(无人操作)可能出现漂移事件进而翻车，根源是
  轮腿模型静止平衡的慢漂移+刹车倾角“后仰前栽”耦合，参数层无法根治；
  日常驾驶(<90s)正常，勿长时间无人看管。

## 12. 手动腿长按键 E/Q(2026-08-04)

GUI 新增 E/Q 手动腿长控制，配合 10.1 的腿长分段模型使用：

- `E` 伸长腿：`leg_extend` 目标 `-0.250`，车体升高(z 约 0.145)。
- `Q` 缩短腿：`leg_extend` 目标 `+0.250`，车体降低(z 约 0.064)。
- `SPACE` 跳跃：下蹲(0.20s) -> 蹬伸(0.18s，腿执行器直接打 ±5 扭矩爆发) ->
  空中(0.55s，腿保持全伸) -> 落地缓冲(0.80s)。
  实测车体弹到 bz≈0.5~0.6(真离地)，跳跃中忽略重复触发，起跳姿态门槛
  (|pitch|<6.9°、|roll|<4.6°)防止从歪斜状态起跳。
- 左右出力不均(侧翻)修复：下蹲准备阶段按 roll 补偿(KP=6)摆平车体，
  蹬伸阶段半增益(KP=3)保持对称。正常起跳时 roll 摆动从 180°翻车降到
  ~20-30°，多数连跳可恢复。
- 已知限制：暴力起跳的飞行角动量不可控，落地偶尔仍会摔翻(不同 run 随机)；
  参数层无法根治，真正解决需要空中姿态控制(飞行中用前后/左右腿差动调整
  pitch/roll)，属后续专项功能。

### 12.5 侧翻自救(2026-08-04)

- 检测：`|roll|>66°` 或 `|pitch|>60°` 进入自救，回正(<46°)退出；期间轮扭矩清零。
- 控制：按**腿负载**判定着地侧(哪边腿受力大就伸哪边，不依赖 roll 符号的
  朝向判断)，0.35s 推/0.25s 松脉冲循环避免连续推过冲。
- 效果：能从部分侧躺姿态翻回(连续推实测可从 +103° 抬到 +60°)，但从
  “侧倾+后仰”角姿态(roll~100° 且 pitch~30°)撬不动——腿没有足够杠杆，
  不同摔姿自救成功率不一。属尽力而为，非全姿态可靠。

### 12.6 自救改手动 + 落地软着陆 + 落地防漂移(2026-08-04 末轮)

- 自救改为 **H 键手动触发**(不再自动)，扭矩 6→4 且 0.015/步速率限幅，
  温柔发力不猛砸。实测能把车从 roll 124° 推到 57°，部分姿态可翻正。
- 落地软着陆：空中+落地阶段检测腿负载，触地(四腿总负载>18)后转
  软弹簧-阻尼(KP1.5/KD0.12)，腿让位吸能，不再硬顶。
- 落地防漂移：空中+落地期间轮扭矩限幅 ±8 Nm，防止平衡环在触地瞬间
  打轮造成打滑后漂。实测落地后 bx 稳定在 +0.3m(之前漂到 -2m)。

### 12.7 前栽问题(2026-08-04 收尾)

- 跳跃下蹲阶段车头会短暂前倾(-6°)，落地后也有 ~1.5s 的 -5° 回摆然后回正。
- 尝试在下蹲/蹬伸加 pitch 补偿(KP4~12，前后腿差动)：要么把起跳推成后仰
  (+13~24°)，要么落地后向前猛栽(-59°)或向前漂移(+2.2m)，均比不补偿更差，
  已撤回。
- 结论：前倾是四连杆蹬伸几何的固有现象，幅度约 -6°、可自恢复；
  暴力跳跃下精确控制 pitch 会破坏起跳稳定。当前为稳定版本。

### 12.8 自救关闭 + 轮子先落地(2026-08-04 末)

- 日志确认 H 自救会把翻车车体越滚越歪(+180°→-110° 不翻正)，已默认关闭
  (`SELF_RIGHT_ENABLE=0`)，不再帮倒忙。
- 几何探明：轮子世界 z≈-0.15，前足 z≈+0.04~+0.10——**轮子永远是最低点**，
  空中保持腿全伸(-0.25)时轮子必然先着地，符合“提前伸长腿+轮子先落地”策略。
- 落地缓冲分两段：空中+触地瞬间轮扭矩限 ±6(防打滑后漂)；
  确认落地后放开到 ±25，让平衡环用轮子主动救姿态(轮子着地才能做更多挽救)。
- 实测：落地 pitch ~1.7s 回正、bx 稳定 +0.2~0.3m、不漂。剩余问题仍是
  飞行姿态旋转——只有空中姿态够平时轮子先落地策略才成立。

### 12.9 自救重做：腿摆角摇摆(2026-08-04 最终)

- 按用户方案重做：腿摆角先向后保持(轮子落地)、再向前保持(借轮子支点翻身)，
  腿伺服跟随摆角，温柔不猛砸。
- 实测(90°侧倒测试)：
  - 连续摇摆(±0.6/±0.8 rad)：roll 从 124° 降到 76°；
  - 时序保持(向后1s/向前1.5s)：124° 降到 85°(平躺侧)。
- 结论：能显著减小翻倒角(后仰倒→平躺侧)，但**平躺侧是稳定平衡点**，
  12kg 车体腿撬不动(无杠杆)。完整翻身需要机构级改动(更强/更长腿、
  配重、尾翼等)，控制层已到极限。
- 松开按键后保持当前位置不回弹：按住 E/Q 持续调节，松开保持当前目标
  (`g_manual_leg_target`)，直到按相反键或 R 复位。
- 同时按 E+Q 相互抵消；变化率受 `ext_step_pb` 限制，约 0.5s 走完全程。

实现要点：

- `balance_set_leg_extend_manual()` 保存手动目标，平衡核心在腿长阻尼参考
  (`ext_damp_ref`) 上叠加该目标，`leg_t` 每侧 +/-0.016 rad 夹紧仍生效。
- `controller.c` 把 E/Q 接入 `update_manual_command()`，与 WASD 一样走回调+
  轮询双保险，并写入行车记录仪按键事件(E/Q)。
- 行车记录仪新增 `leg_len`(实测虚拟腿长，与辨识状态同定义)和 `le_man`(手动目标)
  两列；GUI 遥测显示 `llen=`。
- 无界面脚本 `MANUAL_TEST` 支持 `u`(伸长)/`d`(缩短)，
  例如 `MANUAL_TEST=u@5,d@9 ./controller --headless 10`。

实测(headless, 13s 对照)：

- 腿长变化阶段 pitch 与无按键基线差异约 1~2°，无离地、无冲击、不翻车。
- 启动后前 2-4s 的 -8° 俯仰瞬态是无输入基线同样存在的启动收敛问题，

### 12.1 腿长“按了没反应”修复(2026-08-04)

根因：腿角环 PID 死区 `LEG_ANGLE_DEADBAND=0.012 rad` 与 E/Q 指令幅度
`MANUAL_LEG_EXTEND_MAX=0.012 rad` 恰好相等——目标偏移落在死区边界内，
腿伺服输出为零，实测 `leg_len` 几乎不动(约 ±0.001)。同时小于死区的负载误差
永远不被修正，叠加出持续数分钟的腿长慢漂移。

修复：

- `LEG_ANGLE_DEADBAND` 0.012 → 0.003(明显小于指令幅度，仍保留滤波作用)。
- `MANUAL_LEG_EXTEND_MAX` 0.012 → 0.250(幅度不足时视觉不明显)。
- 腿伺服每侧夹紧 `clamp_leg_extension` 和平衡核心 ext 夹紧从 ±0.016 放宽到
  ±0.260，让 0.250 指令不被截断。
- `LEG_ANGLE_KP` 2.25 → 4.0(腿伺服更硬，跟随更快)。

验证(headless 静止 8s → E 3s → Q 3s)：

```text
E(le=-0.250): leg_len=-0.251 bz=0.145
Q(le=+0.250): leg_len≈+0.03   bz=0.064
```

leg_len 变化约 0.28、车高变化约 8cm，按住约 0.7s 走完全程。
注：腿长是有界的(机械连杆行程有限，不是电机问题)；E 按住升到顶、
Q 按住降到底，松开保持。实测 0.25 幅度全程稳定不翻车。

### 12.2 漂移现状(诊断)

行车记录仪显示“漂移”的实际模式是启动推出 + 远场回程振荡：

```text
0-11s : 启动阶段 pitch 到 -4~-8°，车向前推出 +1.25m
11-22s: 远场回程逻辑(|pos|>0.5m)往回拉，pitch 转 +3~+6°，过冲到 -0.9m
持续  : 在 ±1m 附近来回荡，36s 内范围约 [-0.97, +1.25]
```

这是已知的“启动瞬态 + 回程过冲”问题，不是 E/Q 腿长引入的；腿长修复后仍存在。
下一步建议(可选其一，改动前先确认方向)：

1. 启动不推出：压低启动 pitch 瞬态(腿沉降更快收敛/启动期加轮速阻尼)，
   车就不会到远场，回程振荡自然消失。
2. 远场只保持不追原点：把 `far_field` 分支改成速度清零+位置保持当前点，
   符合“没发指令时维持在当前点”的需求，但车会停在推出位置(约 +1.2m)。

### 12.3 保持当前点 + E/Q 加大幅度(2026-08-04 第二次)

- 新增 `SIMPLE_HOLD_AT_POINT=1`：无手动指令时，`brake_zone`/`far_field` 不再
  `-ret*dir` 追原点，只做速度归零。实测 60s 空闲车停在 +0.5~0.9m 附近，
  不再来回振荡、不再漂到 -5m、不翻车(旧行为 60s 已到 -2m，6 分钟翻车)。
- 启动仍有约 +0.9m 的推出(启动 pitch 瞬态)，随后保持；后续要彻底消除推出
  需压启动瞬态，属于另一项调参。

### 12.4 里程计误差与慢溜(2026-08-04 第三次)

诊断(对照 bx 真值 / xh 里程计)：

- 根因一(里程计误差)：`WHEEL_V_DEADZONE=0.06 m/s` 把 0.02~0.05 m/s 的慢速
  运动整段屏蔽，控制器不刹车、里程计不积分。降到 0.02 后，180s 空闲里程计
  误差从 ~4.5m 降到 ~0.43m。
- 根因二(慢溜)：空闲时 `hold_pos` 只在手动进出时吸附，启动后永远停在原点，
  位置环持续“回程”形成极限环，60~90s 后开始后溜。修复：空闲且低速(<0.03)
  持续 2s 后把 hold_pos 吸附到当前位置；静止死区速度门从 0.20 收紧到 0.02，
  且静止时保留软速度刹车(0.10×body_v)。

实测(180s headless 空闲)：

```text
修复前: 40s 后开始后溜，180s 到 -5.2m，里程计误差 4.5m
修复后: 稳定保持 80s+，180s 到 -3.3m(慢约 40%)，里程计误差 0.43m，不翻车
```

残余问题：约 80s 后仍有一次 -0.3 m/s 的后向扰动触发慢溜(疑似腿沉降完成后
平衡点漂移)，速率约 0.02 m/s。要根治需要进一步整定位置环或腿沉降补偿，
属于后续专项调参。

## 14. 手动驾驶耦合专项：W/S 摆腿"摆一下又回去"、转向带前后溜(2026-09-24)

用户反馈：`W/S` 通过腿摆角度驱动前后运动，但"腿摆摆一下就回去，被什么逻辑
卡住"；`A/D` 转向时平衡和前进耦合(车自己往后跑)。

### 14.1 根因清单(全部有仿真证据)

1. **手动摆腿极性反了**。`sw` 的定义是"轮轴相对基座的前向偏移"：`sw` 减小 =
   轮轴相对车体后移 = 质心相对轮轴前移 = 车前进。旧代码 `W` 给的是 `+SWING_DRIVE`，
   方向相反。headless 实测 `MANUAL_TEST=f`：腿摆打到 +0.030，车 `bx`
   从 +0.67 跑到 **-2.12(向后)**；把符号翻过来同一工况跑到 +5.0。
2. **低速打滑判据开机即锁死**(最主要"卡住"原因)。旧判据
   `|wf|<0.15 && |imu_acc|>0.10` 在静止时恒成立(轮不转 + IMU 偏置/腿摆噪声)，
   打滑标志一旦置位就把腿摆指令**清零**。表现为按 `S`/慢速起步完全不摆腿。
   现改为用融合速度 `|simple_imu_v|>0.2m/s` 做证据(机体确实在动而轮不转)。
3. **固定摆角 + 线性软限速**的结构性缺陷。速度升高后按比例把摆角拉回中位，
   就是字面上的"摆一下又回去"。改为**腿摆速度环**：
   `swing = -Kv·(v_ref - body_v_filt)`，摆角停在维持目标车速的角度上并保持。
4. **前倾角门控硬清零**。`|pitch|>0.15rad` 时直接把 `manual_v/manual_yaw`
   清零 -> 摆角指令瞬间回中位。改为 0.12rad 起按比例收敛、0.30rad 才硬保护。
5. **手动共模扭矩上限贴着工作点**。俯仰环 P 增益 -25，1.2Nm 上限对应仅
   2.7° 误差就饱和，正常巡航一直顶在限幅上，松手刹车 20° 后仰救不回来。
   改为 4Nm(物理上仍由单轮摩擦极限 μ·N·r≈0.52Nm 封顶)。
6. **偏航位置环增益太小**。模型左右腿机构不是严格镜像(轮几何 x 偏移差 ~3mm)，
   直线行驶有恒定偏航扰动；`SIMPLE_YAW_POS_KP=1.2` 时按 `W` 直行 12s 车头偏
   -35°、横漂 5m。提到 3.0 后同样工况只偏 -3.8°、横漂 0.6m。
7. **手动转向分支把车往后推**。纯转向时腿锁在当前摆位、速度阻尼关掉，
   而"当前摆位"对应质心在轮轴后方 ~1.3m/s² 的静差 -> 按 A/D 车自己往后加速。
   现在手动统一走"腿摆速度环 + 位置保持"(`v_ref = -Kp·(pos-hold_pos)`),
   前进/后退/转向三个状态共用同一条链路。

### 14.2 关键标定

- `SIMPLE_MANUAL_SWING_TRIM=0.016`：手动硬伺服下"零速平衡"的摆角偏置。
  标定方法：手动零指令跑 10s，看里程计漂移方向，往反方向调。
- `SIMPLE_VEL_DAMP` 2.0 -> 4.0：自动静止慢漂从 0.09m/s 降到 0.017m/s。
- 机动性实测(headless，12s)：`f` +6.5m/末速 0.94m/s；`b` -4.4m/末速 -0.85m/s；
  `l/r` 前后漂移 |dx|<0.25m 且能原地转；`f@9,b@16` 前进后能反向。

### 14.3 仍未解决(留给下一轮)

- 原地转向 A/D 不对称：同样的 0.4rad/s 指令，D 转 -128°，A 只转 +46°，
  疑与模型左右腿非镜像的偏航偏置同向/反向有关。
- 偏航环在 50Hz 更新 + 8ms 速率滤波下相位裕度仍然偏小，手动转向时差速扭矩
  仍在限幅附近小幅振荡。
- RL 跳跃在本工作区本来就是失败的(参考二进制 `RL_JUMP_AT=3` 同样 abort)，
  本轮改的 `SIMPLE_VEL_DAMP`/`SIMPLE_YAW_POS_KP` 会改变它 abort 的时间点，
  属于副作用但非新增故障；跳跃专项需要单独处理。

## 15. roll 找平环极限环："车来回摆动、腿不是定长"(2026-09-24)

用户现象：静止时车体左右来回摆，差动腿长一直在抽，腿长看起来不是固定的。

### 15.1 根因：ROLL_STAB_KP 比几何单位增益大 63 倍

`balance_step_origin.inc` 的 roll 找平环输出"左右差动腿长" `leg_side_extend`：
`side_ref = -KP·roll - KD·roll_rate`，限幅 ±`ROLL_STAB_MAX`(0.04m)。

几何标定（MuJoCo 正解）：轮距 0.252m，差动腿长 d 让机体反向找平约
`2d/轮距`，所以**完全补偿 1rad 侧倾只要 d=0.126m**，即单位增益 KP≈0.126。
旧值 **KP=8.0** 是它的 63 倍：`|roll|>0.005rad(0.29°)` 就吃满 ±0.04m 限幅，
整个环退化成继电器式 bang-bang，必然产生极限环。

实测（静止，无手动指令）：

| 参数 | roll 峰峰 | 差动腿长峰峰 | 20s 横向漂移 |
| --- | --- | --- | --- |
| KP=8.0 KD=0.02 (旧) | 11.89° | 0.0508 m | - |
| KP=0.30 KD=0.009 (新) | 0.30° | 0.0024 m | by=+0.02m |

加 0.3Nm 侧倾力矩扰动：旧参数 roll 峰峰 8.39°、腿长峰值 0.010m；
新参数残余 roll 0.19°、峰峰 0.23°、腿长 0.0011m(无振荡)。
1.0Nm 扰动下新参数残余 0.46°，仍然无振荡。

### 15.2 连带影响

修好 roll 环后另外两个现象一起消失了：

- **手动转向 A/D 不再带前后溜**：静止 roll 峰峰 0.30°，A/D 原地转时
  `|dx|<0.01m`；之前 roll 环一直在抽，把车"摇"得前后漂。
- **A/D 转向幅度变对称**：D -38.8° / A +39.1°（修复前 -128° / +46°）。

### 15.3 手动摆角限幅不能顶死

修复 roll 环后出现过一次"按 S 车完全静止"：`SIMPLE_MANUAL_SWING_MAX`
沿用自动位置环的 ±0.03，速度环的摆角参考被限幅顶住，腿伺服把车"钉死"。
手动摆角限幅改为独立的 ±0.05（关节约 ±27°，实际巡航只用 0.014~0.028）
后 S 恢复 -0.75m/s，W +1.17m/s，A/D 原地保持 0 漂移。

### 15.4 顺带修掉的测试钩子缺陷

- `ROLL_PUSH_AT` / `ROLL_TORQUE_AT` 找的 body 名是 `"base"`，v3 里叫
  `base_link`，`mj_name2id` 返回 -1，力从来没加上（测试静默失效）。
  已改为 `imu_body_id()` 自动兼容两个模型。
- `ROLL_TILT_START` 直接覆盖立姿四元数（`qpos[3:7]=cos/sin(half)`），
  结果是让车"躺倒"而不是给 8° 侧倾，该钩子仍未修，需要把倾角左乘到
  立姿四元数上。

## 16. W/S 方向与"原地转圈"(2026-09-24 第二轮实机/GUI 反馈)

用户实测反馈两条：`W` 往后走；`A/D` 不是原地转——转一下位置就偏。

### 16.1 W/S 方向：车头在 -x，改按键层而不是控制环

用 GUI 记录的 `dashcam_*.csv` 对齐按键与位移：按住 `W` 时 `bx` 增大
(12.90→13.31)，按住 `S` 时 `bx` 减小。也就是说"控制环里的前向"是 +x，
而**这台车的车头是 -x**（用户视角）。历史日志(8/30)里 W 也是 +x，
所以这跟本轮改动无关，是"按键到目标速度"的符号约定问题。

结论：**不要在控制环里翻符号**（环内 `v_ref -> 摆角 -> 运动` 自洽，
曲线里 pt/v/sw 的符号关系都是对的），只在按键映射层取反：

- `app_gui.c`：`W -> speed -= SIMPLE_MANUAL_V_MAX`，`S -> +=`；
- `app_headless.c`：`MANUAL_TEST=f -> v -= V_MAX`，`b -> +=`（与 GUI 同符号）。

改完 headless 实测：`f` 走 -x(-1.96m/3s)，`b` 走 +x(+3.00m/3s)。

### 16.2 转向不是原地转：两个独立原因

**(a) 偏航环会"卡死"**：手动偏航速率增益降到 0.4(上一轮为了抑制振荡)后，
速率误差 0.4rad/s 只产生 0.16Nm 差动力矩，而腿伺服对偏航反作用有静摩擦
——实测车转到 ~36° 后 `yaw_rate` 恒 0、车完全静止，按住 A 也不再转。
恢复到 1.2 后 (0.48Nm) 能持续转：headless 按住 A 14s 转满一圈。

**(b) 位置环追不上转向起步的扰动**：手动腿摆变化率限幅是 0.01m/s，
满幅 ±0.05 需要 10s，而转向起步时的前后扰动只有 1~2s ——原地转时车会
先滑出 0.7~1m 再停住。放开到 0.03m/s(满幅 1.7s) 后：

| 工况 | 改前 | 改后 |
| --- | --- | --- |
| A 原地转 12s | dx=-0.97m dy=-0.21m (且转 36° 卡住) | **dx=+0.01m dy=-0.33m** (转满 184°) |
| D 原地转 12s | - | dx=-0.00m dy=+0.22m (转 179°) |
| 先开再转 | dx=-2.20m dy=-3.32m | dx=-0.16m dy=-0.26m |

顺带：`A/D` 纯转向分支不再把速度阻尼置 0（原注释认为 `body_v` 是差速伪影，
但实测它与里程计位移一致且可达 1.2m/s），改成保留
`SIMPLE_MANUAL_TURN_VEL_DAMP=4.0`，与 park 阻尼叠加。

## 17. 转向改为"双腿叉开"(差动腿摆) (2026-09-24 第三轮)

### 17.1 实现

新增一条虚拟执行通道 `leg_swing_diff`（m）：
`robot_control.c` 里腿摆参考改成 `sw_ref_l = swing_ref + diff`,
`sw_ref_r = swing_ref - diff`；`diff` 由偏航角速度误差闭环给出：

```
diff_ref = -SIMPLE_MANUAL_YAW_LEG_KP * (yaw_rate_filt - manual_yaw)
```

差动把轮轴线在水平面内"拧"一个角度，由闭链腿几何直接产生偏航力矩，
不像轮子差速必须先把轮胎推滑起来，也不带前后推力。轮子差速环保留做

`YAW_LEG_MAX=0.045m`、`YAW_LEG_RATE=0.06m/s`、`YAW_LEG_SIGN=+1`。

配套：手动（含纯转向）一律用**硬腿**伺服（原来纯转向用软腿 kp=300/死区
0.02，会把 ±0.045 的差动指令吃掉大半）。

### 17.2 位置保持增益重标定

## 19. 转向"一卡一卡 + 慢"：偏航环路与制动项打架 (2026-09-24 第四轮)

用户反馈：转弯不流畅、一卡一卡、还慢。

### 19.1 定量化抖动

用无界面按住 A 转 15s，看稳态偏航率的统计量(CSV 20Hz)：

- 均值 0.25rad/s，但 **std 0.24、峰峰 1.5rad/s**（抖动和均值一样大）。
- 逐帧看轮速：50ms 内从 -14rad/s 跳到 +22rad/s —— 轮子在被来回砸。
- 静止稳态的偏航率 std 只有 0.0006，说明抖动是真实自激，不是传感器噪声。

### 19.2 两个根因

**(a) park 停车阻尼 + 手动转向阻尼与腿摆位置环对打**
`SIMPLE_PARK_VEL_DAMP=4` 在手动档也没关，加上上一轮为压滑移加的
`SIMPLE_MANUAL_TURN_VEL_DAMP=4`，两个共模轮扭矩项和"叉腿转向+腿摆位置
保持"作用在同一个轮子上。实测两者的参与：

| 配置 | 偏航率 std | 离起点 | \|pitch\|max |
| --- | --- | --- | --- |
| 都开(原) | 0.244 | 0.18m | 2.3° |
| 关转向阻尼 | 0.219 | - | - |
| 关 park | 0.275 | - | - |
| **都关** | **0.199** | 0.06m | 0.2° |

结论：手动模式下 park 阻尼必须让位（`park_scale_pb=0`），
`SIMPLE_MANUAL_TURN_VEL_DAMP` 回 0。位置保持由腿摆环负责，不需要轮上再刹。
顺带 W 巡航从 0.76 提到 1.05m/s（少了刹车项）。

**(b) 偏航环 50Hz 的相位滞后**
偏航环原来 20ms 一次更新 + 8ms 速率滤波。把它提到每步 1kHz 执行后，
同样增益下抖动 0.219->0.193，于是可以再提高增益：

| 增益(1kHz) | 偏航率 | std | 离起点 |
| --- | --- | --- | --- |
| 1.2 | 0.38rad/s | 0.193 | 0.12m |
| **2.4** | **0.47rad/s** | **0.183** | 0.12m |
| 4.0/8.0 | 0.49rad/s | 0.23 | 0.12m |

取 2.4（再高开始激发 ~8Hz 偏航轴机构谐振）。

### 19.3 实测

| 工况 | 改前 | 改后 |
| --- | --- | --- |
| 按住 A | 0.25rad/s、std 0.24、离起点 0.18m、\|pitch\|2.3° | **0.47rad/s、std 0.18、离起点 0.12m、\|pitch\|0.3°** |
| 按住 D | - | -0.47rad/s、std 0.17、离起点 0.12m |
| 按 Z 小陀螺 | - | 0.55rad/s、离起点 0.07m |
| 静止 12~20s | - | 漂移 0.000m/s |
| W 巡航 | 0.76m/s | 1.05m/s |

A/D 转向目标速度从 0.4 提到 0.6rad/s（现在实测能到 0.47）。

### 19.4 遗留

偏航率仍有 std≈0.18 的 ~8Hz 抖动，怀疑是偏航轴(腿闭链侧向刚度 + 轮
侧向抓地)的机构谐振，或者是 MuJoCo 网格轮接触的数值抖动；再提高环增益
会激发它。要根治需要给偏航轴做陷波或在腿侧向加阻尼。

## 21. 取消陀螺漂移的真正根因 + 转向/陀螺速度 x2 (2026-09-25)

用户反馈：关闭小陀螺车会漂移；转弯和小陀螺太慢要 x2；中间还有停顿。

### 21.1 取消陀螺后漂移：松手不进刹车阶段

读用户实测日志 `logs/dashcam_20260925_001156.csv`（Z 在 1.64s 开、11.09s 关）：
关掉后车从 0 加速到 **2.79m/s**，`sw` 却是 0（腿摆没在刹车）。

加 `SWDBG=1` 打印内部量才看清：松手瞬间 `post_manual=0` ——
`balance_api.c::balance_set_manual` 里

```c
g_balance.post_manual = (fabsf(g_balance.manual_v) >= 0.05f) ? 1 : 0;
```

**只有按过 W/S 才进刹车阶段**，纯转向/小陀螺松手时 post_manual=0，
于是 `leg_ref_pb` 直接掉回 0。而 0 是"往前跑"的配平点(手动平衡配平在
`SIMPLE_MANUAL_SWING_TRIM≈0.016`)，车被这个静差一路推着加速。

改法：只要松手时车/指令还有动静就进刹车阶段：

```c
post_manual = (|manual_v|>=0.05 || |manual_yaw|>=0.05 || |body_v_filt|>0.05)
```

实测（陀螺 1.6~11.1s 后关）：峰值速度 2.79 -> 0.14m/s，位置偏移 4m -> 0.15m。

### 21.2 速度 x2

命令加倍本身没用（偏航差速会被 0.6Nm 上限卡住），必须同时放开上限：

| 配置 | 小陀螺实测 | A/D 实测 |
| --- | --- | --- |
| 原(命令1.2/0.6, 上限0.6) | 0.59rad/s | 0.47rad/s |
| 命令x2, 上限仍0.6 | 0.58rad/s(没变) | - |
| **命令x2, 上限1.2** | **1.60rad/s** | **0.92rad/s** |

`SIMPLE_MANUAL_YAW_MAX=1.2`。

## 22. 高腿长转弯失效：配平点随腿长漂移 (2026-09-25)

用户反馈：腿伸长之后转弯又不行了；差动腿摆角度应该和腿长有关；
顺带问 LQR 有没有在用。

### 22.1 LQR 现状：没有生效

- `CTRL_LQR_MIX_GAIN` 对 v3 是 **0**（注释：v3 分段 LQR 模型尚未重新辨识，
  先置 0 关闭）。模块每帧仍在算，但输出乘 0，不参与控制。
- 另外 `CTRL_LQR_LEG_LEN` 门槛写的是 `[-0.30, 0.06]`，而 `s->leg_len` 是
  绝对腿长(≈0.11m)，**永远落不进这个区间**，所以即便把增益打开也不会触发，
  属于移植时遗留的"没重标定的门槛"。

### 22.2 现象复现（`MANUAL_TEST=n@3,ul@45`，`ul`=伸腿+按住 A）

| 腿长 | 转向速率 | 离起点漂移 | \|pitch\|max |
| --- | --- | --- | --- |
| 0.111m(默认) | 0.92rad/s | 0.06m | 0.4° |
| 0.149m(伸腿+4cm) | 0.91rad/s | **0.86m** | 1.6° |

转向速率没变，但**位置保持失效**——车越转越跑。

### 22.3 根因：手动摆角配平点随腿长移动

扫描 `SIMPLE_MANUAL_SWING_TRIM`（都是长腿工况）：

| 腿长 | trim=0.016 | trim=0.006 | trim=-0.004 | trim=-0.014 |
| --- | --- | --- | --- | --- |
| 0.131m | 0.21m | 0.05m | - | - |
| 0.149m | 0.86m | **0.10m** | 0.45m | 1.20m |

腿越长，平衡所需摆角越靠后（负方向），固定 trim=0.016 在长腿时就是一个
不小的前向静差，位置环追不动。

改成"随腿长线性收缩 + 限幅"：

```
trim(L) = clamp(SWING_TRIM + TRIM_LK·(L - LEG_LEN_REF), TRIM_MIN, TRIM_MAX)
        = clamp(0.016 - 0.55·(L-0.110), 0.004, 0.020)
```

实测：短腿 0.04m / 中腿 0.09m / 长腿 0.06m。

### 22.4 差动腿摆按腿长缩放

叉腿的几何效果取决于"腿张角" d/L，腿变长时同样的 d 张角变小。改成
`diff_max = YAW_LEG_MAX · clamp(L/LEG_LEN_REF, 0.8, 1.6)`，保持同一张角。

### 22.5 各腿长实测

| 工况 | 短腿 0.111m | 长腿 0.148m |
| --- | --- | --- |
| A/D 转向 | 0.92rad/s，漂 0.04m | 0.89rad/s，漂 0.06m |
| Z 小陀螺 | 1.59rad/s，漂 0.09m | 1.00rad/s，漂 0.05m |
| W 前进 | 1.04m/s | 0.87m/s |

腿长时转速/速度变慢属于惯量变大的正常现象。默认腿长的全量回归
（陀螺 1.59rad/s、A/D ±0.92rad/s、松手不吃漂、静止零漂、W 1.04m/s）不变。

## 23. LQR 专项结论：从"辨识整机模型"转向"解析模型 + 最小标定集"(2026-09-25/26)

用户要求"小角度内 PID 让位、LQR 独占"，本节按时间顺序记录这条路上被证伪的假设
与最终成立的做法，供后续维护直接引用。

### 23.1 模态基：四个模态、各一个执行器、可算的不辨识

把腿的虚拟坐标写成共模/差模：

| 模态 | 执行器 | 对机体的作用 | 类型 |
| --- | --- | --- | --- |
| `L_c=(L_L+L_R)/2` 共模腿长 | 两侧同伸/同收 | 车高、摆的等效摆长 h | 几何 |
| `L_d=(L_L−L_R)/2` 差模腿长 | 一伸一收 | **roll = 2·L_d/轮距** | **代数(纯几何)** |
| `sw_c` 共模腿摆 | 两侧同向摆 | 前后(质心前后偏) | 几何+摆动力学 |
| `sw_d` 差模腿摆(叉腿) | 一前一后 | **yaw ≈ 2·sw_d/轮距** | 代数(纯几何) |

代码侧本来就是这套基（`leg_extend`/`leg_side_extend`/`leg_swing`/`leg_swing_diff`）。
**roll/yaw 是代数关系，不存在动力学，用 A 矩阵拟合必然失败**（实测 roll 的 5 步
R² 全程 −3~−31），因此 roll/yaw 一律不进 LQR，走几何闭环。

### 23.2 12 状态地面辨识路线为什么不可用（逐条有实测）

1. **闭环偏差**：数据是三环闭环下采的，输入与状态相关，最小二乘的 B 有偏。
2. **一步 R² 是假的**：采样 25ms 时 `A≈I`，"用 x_k 预测 x_{k+1}"天然 0.99；
   递推 4~10 步后多数状态 R² 转负。验收必须用**多步递推**。
3. **归一化指标两头都不靠谱**：R² 被 A≈I 送分；NRMSE 又会被"安静窗口"惩罚
   （中部窗口状态不动 → 分母接近 0 → 误判为差）。最终采用**绝对误差**
   （5 步 RMSE：pitch < 0.5°、wheel_v < 0.05 m/s），与控制目标同量纲。
4. **闭环伺服量不可辨识**：`leg_swing`/`leg_len_diff`/`roll` 在 25ms 尺度上
   "已经跟完"或被代数关系锁死，出现 R²=−1e5 级别的假象（其中 −1e5 是
   分母趋零的**指标假象**，不是坏数据；另有一次是拟合发散，已用列归一化+
   截断 SVD 修掉）。
5. **加大激励反而更差**：误差随激励幅值线性增长（实测 pitch 5 步误差从
   1.0~3.8° 变成 1.6~10.2°）——说明误差来自**非线性**（伺服饱和、打滑切换、
   闭链几何），线性状态空间在该尺度上描述不了。小信号可线性化但信噪比差、
   大信号信噪比好但线性化失效，这是该路线的**精度上限**。
6. **分段/分窗口不能解决**：K 在相邻窗口变号（−5.5↔+13.5），因为两端窗口
   信噪比最差；逐窗口 valid 标志能从机制上避免用它，但救不了精度。

### 23.3 接管通道与 K 的关系（两条实测教训）

- **K 是满矩阵**：未接管的通道会经耦合列污染已接管的输出。只接管共模轮扭矩
  而用满阵 K，实测静止漂 6.65m（比全通道接管 1.51m 还差）。
- **接管哪些通道，K 就必须只在对应的可信状态上设计**（状态裁到
  `[pitch, pitch_rate, wheel_v]`）——这一条是结构性的，不是调参能绕过的。

### 23.4 解析俯仰模型（当前采用）

`scripts/tools/analytic_pitch_model.py`：直接读 MJCF 得到

```
m = 2.426 kg, r = 0.043 m
h(L_c) = 44.3 ~ 56.4 mm   (质心相对轮轴高度, 随腿长变化)
θ̈ = (g/h)·θ + τ/(m·h·r),  v̇ = τ/(m·r)     (状态 [pitch, pitch_rate, wheel_v])
```

用**连续 CARE**(`scipy.linalg.solve_continuous_are`)解 LQR，输出
`lqr_pitch_analytic.h`（7 点 (L,h,K) 查表）。关键结论：

- **K 与腿长几乎无关**（L=0.090~0.150 全程变化 <0.1%）→ **不需要按腿长分段**
  （对比辨识路线的 11 个窗口 + valid 标志，全是在解决一个不存在的问题）；
- Q=3000 时 `K=[+75.7, +15.9, −1.83]`，1° 倾角对应 ~1.33Nm，**刚好落在两轮
  摩擦极限附近**——解析解自动与物理极限匹配；
- 早期把**连续** A/B 丢进**离散 DARE** 会得到退化解（K=[1.02,0,0]），
  必须用 CARE 或按 1kHz 正确离散。

### 23.5 符号必须逐列对齐（最容易踩的坑）

解析模型用教科书约定（正共模轮扭矩 → 正 θ̈、v 前进为正），部署侧相反：

- `pitch`/`pitch_rate` 两列要取正；
- `wheel_v` 列要**再翻一次**（因为部署状态 `wheel_v = 0.5(lw+rw)R` 前进时为**负**）。

实测：整体翻符号能修好 pitch（静止 5.13°→1.93°）但速度项变正反馈（静止漂 3.05m）；
**逐列对齐**后静止漂移回到 0.03m。

### 23.6 实测对照（解析 LQR 接管）

| 工况 | 三环基线 | 解析 LQR(Q=3000) |
| --- | --- | --- |
| 静止 | 0.01m / \|pitch\|0.01° | 0.04m / 0.98° |
| W 巡航 | 7.29m / 3.05° | 7.54m / 3.05° |
| A 转向 | 0.16m / 0.43° | 0.14m / 1.86° |
| Z 陀螺 | 0.18m / 0.49° | 0.09m / 1.90° |

残留的 ~1.9° pitch 出现在转向/陀螺工况，来自侧倾/偏航对俯仰的**耦合**
（差模腿长与叉腿动作产生的 pitch 扰动），不是俯仰环增益不足；继续加 K 会超过
两轮摩擦极限。

### 23.7 部署误差与最小标定集（用户口径）

| 量 | 现实来源 | 是否需辨识 |
| --- | --- | --- |
| 质量 m | **称** | 否 |
| 连杆长度 / J 几何 | **量**（误差不大） | 否 |
| 电机常数 | **厂方给出** | 否 |
| 惯量 J | **必须辨识**（一维：已知轮扭矩→测角加速度） | **是** |
| 质心前后偏 dx | **必须测试**（静平衡测试：找零轮扭矩下静止的摆角 = `sw_trim`） | 测试 |
| IMU 安装角 | **一次性水平标定**（放水平台读一次固定偏置） | 标定 |

要点：
- **IMU 零位不能取上电位置**（上电姿态随机、可能手持或坡上）；IMU 靠重力给
  **绝对**姿态，需要标定的只是**安装矩阵**这个固定旋转。
- 解析模型给"结构与动态"，装配/质心误差由 `sw_trim`(静平衡测试)与惯量辨识补上；
  在线慢积分只作兜底。这正是实际平衡机器人的做法：**不是算得准，而是
  算个好初值 + 让标定量兜住**。

### 23.9 更正：关于"L 与 sw 共线/自由度只有 1"的错误结论

本轮曾用临时脚本"直接设 qpos + `mj_forward` 读轮轴位置"来数值求 (L,sw) 雅可比，
得到 `dL/dq1 = dsw/dq1 = 0`、耦合角 180°、`cond = inf`，并据此推断"L 与 sw
在关节空间共线、真实自由度只有 1 个"。**该结论作废**，原因：

- `mj_forward` **不会把 qpos 投影到闭链的 equality 约束上**；
- 这条腿是闭链，运动学**树**里到轮子的路径只经过其中一个驱动关节，另一个在
  树上属于旁路 —— 扰动它当然"零响应"，于是矩阵降秩。

正确的做法是仓库里既有的 `scripts/tools/ident_leg_joint_map.py`：用**闭链牛顿求解**
（约束一起解）得到 J，其 J_L0/J_L1、J_S0/J_S1 均为非退化。

仍然成立的实测事实（与上述错误测量无关）：可用腿长窗口的硬阈值、摆向在两端
改 4cm 无响应、B 降级在长腿端把漂移从 −1.28 归零、多段小陀螺只有中段可用
(0.112m: 1.58rad/s/漂0.11m；0.088m 侧翻；0.156m 前后翻)。两端不稳的机理仍需
用闭链求解测量 J(q) 的条件数、腿长伺服的力方向(竖直/横向比)、以及差模腿长的
roll 权限来定位。

第二次尝试(设关节角后用 600 步刚性 PD "settle" 再数值扰动求 J)同样**不可用**：
得到的 J 元素量级离谱(dL/dq1 从 2.3 跳到 −102)、相邻腿长耦合角在 9°~178° 之间
乱跳、条件数 7~56 无规律。原因是闭链在无重力/刚性 PD 下并非唯一收敛到约束流形，
被动关节的收敛状态不一致、轮关节自由漂移，测出的不是真实的工作位形。

**结论：不要手搓闭链运动学测量**，应使用仓库既有的
`scripts/tools/ident_leg_joint_map.py`（闭链牛顿求解 + 空中辨识），它的
J_L0/J_L1、J_S0/J_S1 ≈ 0.05~0.07 非退化，且与空中辨识出的腿长/腿摆二阶环节
(`F_sw=0.208swdd+36.37swd+700.4sw`、`F_L=-0.001Ldd+25.47Ld+1359.3L`)自洽 ——
这反证 (L,sw) 的 2 自由度结构是真实的。两端不稳的机理若还要查，应基于该工具，
而不是临时脚本。
